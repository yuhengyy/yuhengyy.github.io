### 状态同步 MMO 案例课程

#### 1，搭建客户端基本业务框架

主要是类似之前的框架小课程，整合系统逻辑和服务层逻辑（这里服务层可以看作 Utility 工具层）

与 QFramework 不同的是（以后 QFramework 简称 QF），这里使用大多数是 PERoot.Instance.Svc 或者 PERoot.Instance.Sys，而不是 QF 里面的 this.System<Svc>().Function 或者 this.System<Sys>().Function

所以率先书写的是 PERoot，整个项目的根，之后是接口 ILogic 和 IAwake，IUpdate，IDestroy，让非 Mono 都能通过 PERoot 注册，系统层和服务层使用不同接口进行初始化让自己成为 PRRoot.List 里面的各种接口进行不同的生命周期

重点是 BaseMode 定义游戏模式，让不同模式进行退出和进入可以清理和初始化（类似状态机），比如默认是登录模式，进入之后是角色创建模式，最后才是进入游戏到主城游玩模式

**系统层：AcctSys，StageSys，RoleSys，TaskSys
服务层：TiemrSvc，ResSvc，EvtSvc，NetSvc，AudioSvc，UISvc**

UI 存在一个 WindowRoot，里面提供了许多 Function，利用泛型和递归，传入名字和查找组件的类型则准确找到，或者 Img 和 txt 显示隐藏，颜色，文本等改变重载

UI 的功能跟随上述的 BaseMode 进行不同 UI 的显示隐藏（但是我觉得违背了 MVC 准则，这位老师很喜欢写一块，但是又因为后续要接入 Net，所以我又觉得这些无关大雅，因为 Model 本来就不在自己这，这个准则无非是上述的 MP（ModelPanel）框架去掉 M 变成了 P（Panel）框架，看上去是一团糟，只有 Panel，但实际上不是）

不过 UI 之间解耦不错，除了不同大型面板，登录，弹窗，对话，加载等，还因为主城功能多，还分类成对话，任务，玩家，血量，技能等分类的 Comp，野外或者副本不需要任务和对话，能不同模式看到需要的不同 UI 组件，而且我比较难受的是使用方法

PERoot.UISys.LoginWnd 或者 PERoot.UISys.MajorWnd.HPItemComp，虽然这位老师因为其框架遵从子类父类互相存（在上述 ILogic 里面初始化），所以实际上是 UISys.LoginWnd，MajorWnd.HPItemComp 这种方式调用，但是我还是觉得怪怪的

第一章就是这样，通过搭建框架，完成系统控制游戏模式切换，实现登录模式，进入之后是角色创建模式，最后才是进入游戏到主城游玩模式（暂时未接入 Net,登录用的是虚拟消息）

#### 2，搭建服务器基本业务框架

补充，第一章引用了插件《通用 UI 事件监听器》，但实际上是写在 WindowRoot 的 Function 里面的事件注册工具，监听按，拖，抬，点，并且加回调，和 onclick.AddListen 差不多，但是方便的是可以知道其他行为，后续的轮盘就是依据此工具开发的（回调拖拽点并更新位置）

之后就是服务器，引入 4 个插件

- 从零开发跨平台通用日志插件（object 增加扩展，随时打 log，warn，error，还有不同颜色等）
- 高性能定时系统实现（计时器，没啥好说的，就是增加 Task 去控制定时调用事件）
- 通用消息发布与订阅机制（也叫事件中心，单例调用 EvtScv 去增加事件 key 和回调函数，触发 key 就调用那个函数了）
- IOCP 高性能 TCP 通信（序列化基于 json，功能和我之前写的异步+多线程的 TCP 通信项目差不多，但这个好像更好）

服务器最初搭建抽象，很多概念都是互相跳转，所以完全跟不上也不知道作用，我不多说，结构大致是

> -Main（最初方法，初始化启动器）
>
> > -- BattleLaunch（包含多个世界容器）
> >
> > > --- WorldContain（每个世界容器存在多个事件）
> > >
> > > > ---- World（主城世界，野外世界，副本世界）
> > > >
> > > > > ----- WorldMgr（例如野怪生成）
> > > > > ----- WorldComp（AOI 和寻路 Nav，这一章没有做，但是声明了类）
> > > > > ----- Role（角色在服务器的组件，存在于 World）
> > > > >
> > > > > > ------ RoleComp（角色的组件，例如 MoveComp，这一章没有做，但是声明了类）

这一章完全就是不同类的生成和框架搭建，这个全部都是异步+多线程，BattleLaunch 可以根据 WorldContain 的容量创建玩家要进入的世界（实际上也就是判断里面有几个 World，其中主城 World 配比 x，野外 World 是 20，副本 World 是 10 这样的算法，去得到最低的容量 WorldContain）

到最后，这一章的游戏进度没有进展，功能大致为：Client 接入了 NetSvc，Server 会按照层级逐步生成，最后创建一个世界和 Role，然后 Role 挂一个 NetComp（继承 RoleComp）单独和 Client 的 NetSvc 进行通信，完善之前的虚拟消息为真实从服务器拿取的 NetMsg

虽然不是从这时候察觉的但是这时候我整合了 NetMsg+CMD 的终极作用

**CMD 有各种请求，和各种回应，例如登录，注册，创建新角色等等等等
而每一个 CMD 的枚举都存在一个 ReqPack 放在 NetMsg 里面，大多数情况下 NetMsg 的包只有一个有效
而服务器和客户端就是在接收 Token 消息，在底层反序列化然后得到 NetMsg 后，通过 CMD 的枚举判断我该读取哪个 ReqPack（client 发，server 收）或者 RspPack（client 收，server 发），然后做出相应操作**

#### 3，服务器寻路和 AOI 视野算法

导入 Nav 地图和 AOI 插件到服务器
这一章基本上没自己的逻辑和框架，没多少思想,就是用工具

逻辑基本上就是每个服务器的 Role 存在 AOIComp，AOIComp 存在一个<int,AOIComp>字典存储

服务器的 World 存在 AOIMgr
然后服务器的 AOIMgr 感觉哪个玩家是进入视野，则同步给其他玩家，传入唯一 uid 和 RoleData

客户端收到了数据包和该玩家需要创建的位置和方向则利用自己的 ResSvc 进行创建，而且服务器的 AOIMgr 会控制 Enter 和 Exit，让服务器的 Role 和 Client 的玩家做出不同操作（例如服务器就是不进行移动同步的广播，当然这是之后的内容，客户端则是销毁该玩家模型）

寻路则是有一个多边形漏斗算法插件，给出起始点和末尾点，就能把数据传入 Client 的玩家上（Client 玩家本身也有一个这样的插件，但用的是 Unity 自带的 Nav，之所以客户端和服务器都有，主要是为之后的怪物寻路做铺垫，因为怪物属于服务器权威）

#### 4，客户端移动同步和预表现

通过算法同步延迟和追击

**重点为，只同步玩家操作的改变，然后服务器计算，并且校验，然后同步给其他客户端**
延迟怎么办？？
通过方向向量+速度+延迟时长，进行操作玩家位置的预计算，保证在同一时间，两个客户端和服务器都看到的差不多
然后每 3 秒再继续核心定位一次的心跳消息（心跳消息也用在缓存上面，玩家需要 10 秒未重连则销毁，不然服务器还是默认它呆在原地）

#### 5，任务系统和 NPC 对话系统

完全的 Unity 本身的业务，唯二联网的是

- TaskData 的获取然后在 UI 表现任务信息
- Task 状态的改变请求（例如完成任务，接取任务，领取奖励）

任务完全在客户端进行表现，寻路是依赖 Unity 的 Nav 计算核心移动点位，然后客户端自动操作玩家的移动和方向

> （这里不使用服务器寻路是因为老师说，玩家可以操作的，没必要在服务器进行寻路，实际上只要核对接取和完成的时间差，和数据报本身消息是否有误即可，我认为不保障安全，还可以在存储一个唯一会变化的 Token，这里指字符串令牌，每次登录创建，领取奖励和完成任务需要这个 Token 无误）

#### 6，公共地图怪物和血条管理

公共地图怪物没啥好说的，就是配置怪物的位置种类群集数等等等，利用之前服务器的 AOIMgr，向玩家传递 MonserData 告诉哪里要创建怪物，不过在 World 下存在一个 MonsterMgr 控制怪物新生成

血条也只是 UI 系统变种，只在客户端生效，若存在怪物则把 MonsterData 的 Pos 传入 UI 系统然后生成相关血条在 UI 上面

#### 7，核心战斗流程和伤害表现

这里就很麻烦了，首先还是创建 Skill 配置（普攻算作 0cd 技能），流程复杂

**大概就是，服务器和客户端都存在 Skill
默认玩家这里请求合法，保证流畅性，玩家按下，就继续普攻**

**但正因为普攻存在前摇**

在前摇的时候 Client 发出请求，发送需要打的敌人和伤害还有自己位置等一系列数据包

因为怪物是服务器权威，所以服务器还会进行校验，校验各种消息，比如位置，是否友军，伤害等校验完毕后会发送一个击打成功的回应

所以在前摇期间，客户端不卡，收到服务器回应也就在某个时间段更新 HPItemComp，飘字+血量减少
