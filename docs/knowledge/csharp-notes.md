# C#

### 最初的方向

首先就是学习 C#，把曾经的知识拾取起来，因为工作变动原因，上一份工作为逆战，项目使用 UDK 和 UnrealScript 进行开发，开发环境导致学习方向的不同，半年没有触碰 Unity 去制作游戏了，偶而看的教程也是 Unity 相关的浅显的一些小工具和程序员相关的视频

> 但不是没有收获
> 1，例如[视频：不应过度嵌套代码](https://www.bilibili.com/video/BV1xZ421M7mY "最好的markdown教程") ，引起自己思考，回想了自己的习惯，我也比较喜欢在使用 UnrealScript 使用自己开发的小逻辑或者工具进行封装，然后防止深度嵌套，例如某个技能是散弹，则矩阵变化功能进行封装，例如某个技能需要逐渐扩散的预警，则封装 ValueChange 到一个管理器统一管理
> 2，例如[视频：避免不良命名习惯](https://www.bilibili.com/video/BV1WK4tzTEM4 "最好的markdown教程") ，我为什么命名规范+多注释，因为不熟悉 UDK 和 UnrealScript，导致我在看一些老项目代码的时候，完全不理解代码的含义和逻辑，为了让上个大版本写的内容在下版本也能使用，以及策划配置能够理解，所以命名规范和多注释是必须的，比如 AD36 和 AD38 都存在散弹技能，可以使用上述的矩阵变化功能，还有扩散预警功能，甚至美术给我资产后的 Line 的使用，场景资产的开门关门（我主要做 Boss，Boss 战要控制场景关门）
> 3，跟随 Boss 漂浮的武器同步卡顿，则使用挂载插槽点的方式，使武器成为 Boss 模型一部分，而抛掷技能则隐藏并生成一个新的武器模型进行抛掷，抛出的武器，回收的武器，跟随的武器，是三种，在模型隐藏变化的时候，利用特效遮住切换的卡顿
> 4，UDK 无光照系统怎么办？用透明模型+贴花工具，伪装成探灯，但实际上是一个透明模型在移动，贴花在地面上
>
> **但总的来说，半年没碰 C# 和 Unity，导致知识点遗忘严重，所以决定重新学习 C#**

首先就是学完唐老狮的 C#四部曲

大部分内容都是很久以前就会，但是不知道具体实现，都是会用但是也就只会用

- 所以最重点的应该就是自己去创建了一个泛型 List 和泛型 Dictionary，实现相关类似 C#自带的 List 和 Dictionary 功能，
- 比较难的是迭代器和反射和特性，知识不多但主要是精通难（例如反射，知识少但变化强，能非常抽象整合功能）

- 结尾就是自己写大多数常用排序，选排，快排，插排，希尔实际上大学前就对常用排序就很了解，但是没有亲手写过，又重新巩固起来

（课程有相关练习，基本上一个不落，最后大项目实践实现了贪吃蛇和飞行棋，因为纯靠刷新控制台文字进行游玩，感觉比 Unity 同类型游戏还麻烦，好处是练习了自己的纯逻辑思维和断点调试能力）
