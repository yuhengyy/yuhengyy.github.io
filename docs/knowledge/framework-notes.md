## 框架相关

### 程序基础框架

唐老狮程序基础框架算是我第一次接触的类框架内容，难度不高，自己琢磨也是能够写出类似的内容的，与其说框架，不如说 Tool Function 更加合适，因为其工具作用使用广泛但扩展性弱

例如把单例写成循环自调用泛型，整合资源加载，音频播放器，事件注册模块这些进行封装

难度部分主要在 UIRoot 的创建和对象池功能的实现
但实际上在曾经实习的时候（视辰，制作 MR 游戏）就需要深度了解 Pico 这种 VR 设备对 UI 的支持还有设备操作的映射不同于键鼠，所以当时就制作类似的 UI 功能进行整合
毕设使用了 B 站 up 奥飒姆 Awesom （https://space.bilibili.com/641773200 ）的对象池加载模块
所以难点的对象池框架模块和 UI 框架模块都是我曾经接触过的内容

所以此框架最大用处并非学习，而是复习，熟知我曾经会的内容（正如我开头介绍，很久没碰 Unity 和 C#了）

### QFramework

QFramework 算是我真正意义上接触的第一个框架
我的总结：小，巧，泛，通

> 小：底层代码只有 800 行
> 巧：功能设计合理，易于扩展，特别是 IOC 容器
> 泛：Architecture 设计，随意组合卸载自己设计的模块
> 通：代码通用，例如 QFramework.Toolkits 是基于 QFramework 开发的工具，也就是说 QFramework 这个框架能开发框架

最初学习是很简单的，就是《QFramework v1.0 使用指南》，把游戏变成了四层并且用命令和观察者模式互相调用数据

- View（Controller）：用户摸得到，控制的了，看得到的，大多数指 UI 控件和角色操作控件
- System（Controller），作为中介传递操作和同步数据，因为 Unity 的 UI 框架适合 MVVM 和 MVP，所以实际上很少有 System，所以我的理解的 System 是把功能进行封装，让 View 和 Model 能够通过命令和观察者模式互相调用通知
- Model，基础数据，例如血量，金币，杀敌数，或者角色数据，关卡配置等等
- Utility，最基础功能，或者说工具
  > - BindableProperty<T> ：把 int 用其存储，然后该 int 就能直接自己增加事件而不是使用事件中心
  > - C#扩展写法：比如 this.Log，txt.SetName，增加日志工具和 UI 工具
  > - ILogic：继承可自动实现非 Mono 类中的生命周期函数，通过不同功能进行周期函数命名，但内容差不多 Awake（Init），Update（Tick），Destroy（Uninit）
  > - DoTween，序列化工具
  > - 总之，都是基础功能/工具

其中 Controller 比较难以分类所以在 View 和 System 都写了，因为游戏操作，特别是 UI，往往是 System 需要得到组件 View 才能控制（但在未来学了 MVVM 和 MVP，感觉方法有多样，没必要拘泥于一些理解上的细节）

提炼的精华：**上层向下用命令传递 Command，下层向上层传递用观察者模式进行监听+通知，数据变化时通知所有需要观察自己的脚本（命令模式+观察者模式）**

理解这些后，我算是真正对框架有基本的了解

但，难也是真难，因为之后我去看了老师真正的实践项目，感觉只有框架老手之后才会有如此敏捷的思维和疯狂跳转的功能和实践

我跟着学习了类幸存者游戏，比较难跟上，4 分钟能跳转 10 个脚本去增加一大堆通过框架完善的逻辑和功能

> 大概率是因为我只学了 QFramework v1.0 使用指南，但是根据此框架实际上演变了更多的 QFramework.Toolkits
>
> > QFramework.Toolkits 存在 UIKit，ResKit，AudioKit，CoreKit
> >
> > > CoreKit 又有，ActionKit，CodeGenKit，EventKit，PoolKit
> > >
> > > 所以此框架虽然小，但工具众多

游戏制作需要熟知了整个框架和老师自己开发的工具，哪怕到目前为止，我还没学明白 QFramework 和其制作游戏的流程
不过正因为如此，跟着做完后虽然迷迷糊糊，但反而进步巨大，在只跟着类幸存者这一个项目就能熟悉下面的 MVC 框架

### MVC 框架

MVC 框架，难度骤减，因为先了解的 QFramework ,顺其自然理解，有点像逆向教学，先来个猛的然后学习基础

1，先是全部代码整合到一个脚本（项目逻辑不难，就是在脚本内有数据，按钮，点击按钮让玩家升级然后自己通知自己）

2，然后把参数分类，分别匹配 MVC 三个字母创建三个脚本分别控制，数据（M），UI（V），按钮点击事件（C）（以此制作了一个简单的 MVC 框架）

3，但是因为 UI 组件和事件分开很抽象，还要再获取另外的脚本获取方法名进行调用，因为很多时候都是 Onclick.AddListen+lambda 表达式，于是借此引入 MVP，所有 UI 只有变更的 Text 这种 UI 才放到 View，它只做被改而不进行任何逻辑，所谓的按钮承担了最重要的决策者 P，控制 Model 改变又控制 View 组件改变

4，循序渐进，P 拆分成 VM，框架变成 MVVM，差别不大，无非是把 P 和 V 进行双向绑定，但是和 Unity 水土不服，事件和按钮，本来就是要写一起的

5，之后老师写了自己理解的框架，把 MVVM 的 View 和 ViewModel 合并成 ModelPanel，也就是 MP，数据操作和其状态更新还有事件系统，本可以写一起，本来就需要获取再赋值，或者获取再进行点击事件监听和传递，分开写是浪费（我认为这是最符合 Unity 和其 UI 系统的框架）

6，之后学习了 pureMVC，主要是增加了中介 Mediator，外观 Facade，命令 Command，进行数据的传递，这也是为什么我在上面书写 QFramework 心得时，哪怕自己感觉没学明白但却说 ：_“进步巨大，在只跟着类幸存者这一个项目就能熟悉下面的 MVC 框架”_
**因为这回到了 QFramework 的基础学习里面学到的知识了：数据的传递，数据的层级设计**
